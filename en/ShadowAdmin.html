Overview

One panel instead of a console and a spreadsheet

Most Reforger servers are administered through a mix of RCON, a config file nobody wants to touch mid-session, and a Discord channel where staff describe what they just did. Shadow Haven Admin replaces that with an in-game panel that reaches the whole server — players, bans, identities, the arsenal, spawn rules, the HUD — and a record of every action taken through it.

The design constraint throughout is that the server decides. Panels are a view; the authority is server-side, hooks sit on server components rather than the client that's being audited, and anything a modified client could suppress isn't relied upon. Everything survives a restart in JSON under the server profile — no database, no external service required to run.

It runs as a normal Reforger mod. Six engine classes are extended rather than replaced, so it composes with a vanilla Conflict or Game Master setup instead of taking it over.

The admin hub

One menu, seventeen tabs, driven by mouse or controller. The roster is live, selection survives the auto-refresh, and each tab reconfigures a shared six-slot action bar so the muscle memory carries across.

Accountability

Every Game Master action, recorded server-side

Game Master is the least accountable role on a Reforger server. A GM who spawns a tank, deletes someone's vehicle or kills a player leaves nothing behind but the result, which makes every accusation a question of who is believed rather than what happened.

The audit hooks the server's editable-entity core and the server's kill event — not the editor components, which run on the machine of the person being audited. Spawns, deletions, kills, teamkills and Game Master sessions are all attributed the moment they happen, and a modified client cannot suppress them.

Method of death, not just a name

The engine's kill event carries who, never how. Cause is assembled from the killer's equipped weapon and the victim's last damage context, so a row reads KILL → SomePlayer (Rifle_AK74, gunfire) rather than a bare name. Where nobody pulled a trigger, the damage type answers it — lightning, a fall, fire, drowning.

Artillery gets special handling, because it's the case where accountability normally evaporates: a shell is deleted the instant it detonates and its blast carries no authorship at all. Rounds are marked at the point of impact, and a death close enough in time and space is attributed to whoever fired them — flagged as indirect, never as a hands-on kill. AI kills are excluded: spawning a squad is populating a mission, not shooting anyone.

Why the rollup mattersA single mortar mission used to write two log rows per shell — one spawn, one delete — burying a genuine abuse case under hundreds of Mortar Shell lines and churning the whole record cap in one session. Rounds are now counted per firer and written as one line, so the log stays readable under fire.

Anticheat

Evidence, not verdicts

Seven detectors sample every player on a two-second tick. Each one feeds a score in its own category, scores decay over time, and the response is graduated — the system's job is to put a case in front of a human, not to hand down a sentence.

Detectors

Scores decay at two points a minute. Six points notifies staff; fifteen marks a suspect for review, and only if two separate categories have fired does it reach the top level. Admins, Game Masters, trusted identities, vehicle occupants and anyone inside the join grace window are never flagged — a GM flying around in the editor is expected behaviour, not a detection.

When a movement, airborne or fire-rate detector trips, it writes an evidence file: up to twenty position, velocity and aim samples around the moment, filed per player. Staff get a DM in game; Discord gets an alert once the score clears the notify threshold.

Deliberately conservativeThe anticheat never bans, and enforcement ships switched off. At its most assertive setting it marks a player for review and rubber-bands them to their last valid position. Rate-of-fire detection is off by default until tuned against a live server, because a false positive on a weapon rate is a false positive on someone playing normally.

Identity

Names staff control, and a filter that holds

Players can be given a persistent display name and prefix, stored against their identity and mirrored to every client. Staff can lock a name so the player can't change it. Reserved terms stop anyone calling themselves admin or staff, and impersonation checks block taking the name of an online player or a configured admin even while that admin is offline.

The slur filter is the part that took real work. A plain substring check catches nothing and is beaten by the first substitution anyone tries, so this one normalises first: lowercase, fold leetspeak back to letters, discard everything else, and keep each run of discarded characters as a single wildcard — which is how a Cyrillic lookalike in the middle of a word still matches. Repeated letters collapse, so a stretched spelling matches too, but only in one direction: the term can never skip a letter, which is what starts producing false hits.

False positives are the real cost of a filter like this, so words that hide inside ordinary English are left off the list on purpose, and an allowlist is subtracted from the text before the scan — which is how Scunthorpe and Pakistani survive contact with it. The built-in list isn't editable from config, so an admin can't quietly switch slurs back on.

Arsenal

Control what the server actually issues

Every item in the game catalogue can be disabled, repriced, or granted to a faction that wouldn't normally get it. Filtering happens at three separate points in the engine's own supply funnel, so a blacklisted item disappears from browse lists and weapon racks alike, on both the client and the server.

Cross-faction sharing works either way round: open one faction's catalogue to everyone, or share it into one specific faction. Per-item cost overrides land at the price the UI actually charges.

Disabling an item also takes it off the field. A blacklist that only stops an item being taken does nothing about the people already carrying one — drawn before the ban, looted off a body, or handed over by a GM. Every online player is swept the moment the policy changes, then one player per second continuously, and confiscations are logged so an admin can answer the question when a player asks where their rifle went.

Spawn & HQ

Spawn camping, answered in stages

Two independent systems. Personal spawn protection makes a freshly spawned player invulnerable for a configurable window that ends the moment they fire — detected by watching their magazine, so reloading or swapping weapons doesn't count against them. It never kicks, bans or moves anyone.

HQ protection is the heavier one. Inside their own zone, players can't be damaged and can't shoot — weapons are locked, not just damage disabled, so the safe zone can't be used as a firing position. Enemies approaching a defended HQ escalate through three rings with a grace period at the innermost before anything happens, and every boundary crossing and strike outcome is written to its own log.

Every one of those numbers is editable from the panel while the server runs, and the panel reconciles them — pull the lethal ring outward past the final ring and the others move with it rather than silently producing an impossible configuration. Zones can be drawn on players' maps so nobody crosses a line they couldn't see.

Discord

The server reports itself

Eleven signal types across as many webhook routes as you want, each route with its own switches — send kills to one channel, staff actions to a private one, joins nowhere at all. Every embed leads with the server's own name, so a cluster reporting into one Discord stays legible.

Rate limits treated as a design constraint

Discord throttles a webhook at roughly five posts per two seconds, which a Game Master laying out a base will exceed without trying. Rather than let posts get dropped, world-building churn is buffered and posted as one digest every thirty seconds, while anything a person needs to see immediately — a staff kill, a fire mission, someone entering the editor — posts on its own straight away.

The live status card is a single message per route, refreshed in place: player count, FPS, AI and entity counts, memory, uptime, and a table of active players with their kill record. Chat relay batches lines and wraps them in a code fence, so nobody can trigger a mention from in game.

Player-facing

A compass players actually keep on

Not an admin tool — the part of the mod every player sees. Four compass styles including a live terrain minimap, six colours, six screen positions, adjustable range, scale and opacity, friendly and squad markers, and an optional windage readout that reads the real weather system and gives a crosswind component for anyone ranging a shot.

Server operators set the defaults; players override them from their own pause menu, and those preferences are stored client-side and never touch the server.

Fleet

More than one server

The panel talks to a Pelican-style hosting API — start, restart, stop, kill, run console commands, read live resource usage — and can switch between the servers in your fleet without leaving the game.

For clusters, admin lists and permanent bans push between servers on change, and a live command bus lets an action taken on one box land on another: ban someone on your main server and they're banned across the cluster before they finish reconnecting.

Engineering

How it's built

Server-authoritative by default

Hooks sit on server components, never on the client being audited. Where a check could run in either place, it runs where a modified client can't reach it.

Fail visibly

Systems that go quiet are worse than systems that error. Boot logs say whether each subsystem armed; a silently dropped record leaves a bounded trace explaining why.

Graduated response

Detection notifies before it acts, and acts reversibly before it acts permanently. Nothing in the mod issues an automatic ban.

Plain JSON persistence

Twenty stores under the server profile, human-readable and hand-editable. No database, no external dependency, and legacy paths migrate themselves.

Compose, don't replace

Six engine classes extended, none rewritten. It sits alongside vanilla Conflict and Game Master rather than substituting for them.

Version-resilient

Enum names are resolved through reflection rather than hardcoded, so a game update that renames a value changes a label instead of breaking the build.

Scope

What it deliberately doesn't do

  • It never bans automatically. The anticheat marks and reports; a human decides.
  • Enforcement ships off. Position correction and review marking are opt-in per server, because every server's normal looks different.
  • It doesn't replace the game mode. No custom Conflict, no bespoke scoring — it administers what you already run.
  • It doesn't phone home. Hosting and cluster features point at endpoints you configure; with them off, nothing leaves the box except your own Discord webhooks.
